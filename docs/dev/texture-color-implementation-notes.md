# Texture and render-color source audit

These notes record the source audit that preceded native texture work. File
images, default UV mapping, mapping, bump and normal-map authoring have since
been implemented; see native-textures.md for behavior and evidence. Complete
render-color coordination and production texture certification remain open.

## Existing boundary

`src/core/shader_graph.cpp` admits only authored/validated engine definitions.
The authored set now includes Image Texture, UV Map, Mapping, Bump and Normal
Map. Environment Texture and Texture Coordinate still need host semantics.
Reflection or an HDA catalogue alone cannot establish their compatibility.

`ShaderValue` now covers scalar, string, float3 and owned integer-array parameters. Native
material extraction evaluates promoted values at the requested render time.
Image tiles use that owned integer-array path, with strict integer/range
validation. Native paths resolve expressions/time and HIP-relative locations
before the engine boundary. Revision identity and failed-path notifications
support retained-material reload and automatic file-repair recovery.

## Use the engine image manager

The pinned `ImageTextureNode::update_images` registers filenames and tiles
through the scene image manager. Its SVM compilation obtains metadata and
uses the existing upstream texture-cache path. The noncached background
path can cull tiles from geometry UV usage; interactive rendering intentionally
loads all supplied tiles. Cache-enabled derivative requests are handled by
the engine. These policies should be tested and measured before designing
another cache or implementing host-side per-frame pixel copies.

`src/core/session.cpp` now reads explicit cache/generation settings; automatic
generation remains off by default. The small texture fixture exercises cache
on/off and records preparation, disk bytes, device buffers, refresh and close
on CPU/RTX 4090. Broader workloads still need host/device memory and render-time
measurements before choosing production defaults.
The raw named-volume loaders are a separate data-field path and do not prove
image-texture input interpretation.

UV defaults need explicit Houdini semantics. Existing mesh UV storage is
float2, including subdivision. A missing UV map must produce the documented
coordinate policy or a visible error. Generated/object coordinates, named UV
maps, particles and hair cannot be inferred from the polygon case. A texture
used for true displacement also changes required attributes and mesh variants;
camera-only updates must not reload an unchanged texture.

## Color requires a coordinated session policy

`src/core/color.cpp` reads the active OCIO scene-linear role and supplies display
processors. Current EXR metadata records that role. Existing display tests do
not certify input texture conversion or the complete render working space.

The pinned shader manager obtains its XYZ-to-scene-linear transform from
`ColorSpaceManager`. Its utility implementation contains process-global
processor, colorspace and matrix caches. `check_invalidate_caches` explicitly
requires rendering to stop before relevant configuration changes. It detects
the scene-linear colorspace name; that alone does not establish invalidation
when a configuration changes transforms while retaining the same name.

The integration therefore needs an explicit configuration identity and a
coordinated stop/reconfigure/restart policy for all sessions using the shared
engine state. A display/view or exposure change should remain a presentation
change. A render configuration or working-space change must invalidate affected
shader preparation, texture interpretation and engine color matrices together.
Direct host preference changes and multiple native/Hydra sessions need tests;
relying solely on a panel callback would not cover them.

The engine can warn and fall back when an unknown input colorspace is requested.
The native image adapter now validates named input spaces before committing a
material. Data maps bypass RGB transforms. Alpha association must follow
the image node's documented mode and be tested independently of display
unpremultiplication.

## Required independent fixtures

Use constant and spatially varying float/byte textures with separately computed
linear RGB expectations. Test working Rec.709 and ACEScg, known sRGB input,
scene-linear input, raw scalar/vector maps, channel-packed alpha, straight and
premultiplied alpha, UV orientation/seams, interpolation and extension modes,
UDIM selection, missing/changed files, animated paths, Unicode paths, save/load,
batch, native IPR, shared viewers, cache retention and shutdown. Also test a
texture-driven displacement against independently positioned geometry.

Reference images must not be generated by replaying the same host converter.
Use independent OCIO processors and explicit texel/UV expectations, then a
matched headless engine harness for the performance comparison. Header validation
can reject malformed assets before scene mutation, while failures that occur
during image delivery need generation-safe diagnostics and batch failure status.

## Additional Houdini color evidence

Houdini 22's installed OCIO editor changes the `scene_linear` role when the
artist changes Render Working Space. Its view-transform control reorders
active views. These are distinct changes: a full config cache ID may change
for presentation alone. The next coordinator therefore needs a measured
render-policy identity, rather than automatically restarting rendering for
every full configuration-ID change. Do not call the editor's internal Python
implementation from the integration; it was inspected as behavior evidence.

The public `hou.Color` interface exposes the configuration path, spaces, roles,
color/view transforms and `reloadOCIO`. Verify its transforms against the
native OCIO binding after an actual editor/configuration change. SideFX
documents the scene-linear role, file-rule input conversion, raw data maps
and color-space metadata in its
[Houdini 22 color-management guide](https://www.sidefx.com/docs/houdini/solaris/ocio.html).
The current engine Auto route uses file hints and fallback roles; complete
Houdini file-rule precedence still needs implementation and dedicated tests.

Native frames now hold an opaque immutable source configuration and epoch.
The engine uses an opt-in frozen configuration without changing Houdini's
current-config pointer. All native sessions join before engine/global LUT
caches are replaced; owners then refresh shader matrices, image identities and
affected displacement. Explicit pause, cancel and manual-update preferences
survive the transition. The host uses epoch numbers rather than a boolean
notification to avoid losing rapid consecutive reloads.

The installed HDK exposes `PXL_OCIO::addConfigChangeCB` and matching removal.
The implementation currently observes the public OCIO config/cache identity
from Houdini's supported event loop and polls known input LUT file revisions.
A callback could shorten notification latency, but does not replace the
explicit stop/join/commit protocol.

The isolated reload probe established that HOM, Python OCIO and the native
binding observe public `hou.Color.reloadOCIO` and agree on input processors.
Its original old-frame ownership bug was a real implementation failure. The
pre-fix evidence file explicitly records its reconstruction from tool output;
the probe JSON was overwritten when the first source-snapshot fix was tested.
The initial fixed probe is retained separately. The current independent
`houdini_color_epoch_smoke.py` and actual `houdini_color_ipr_smoke.py` tests
provide stronger lifecycle evidence; see `docs/dev/notes/native-color.md`.

A retained source processor is necessary in addition to retaining the config:
its FileTransforms can reference mutable LUT paths. The installed OCIO 2.5
SDK documents global file-content caching and separate per-config processor
caches. The coordinator clears file contents only after joining native sessions
and compiles fresh processors on the owned config copy. Old source CPU
processors remain alive. Metadata size/mtime watches detect known LUT edits
and retain repair detection after a failed reload. Native tiles use the public
`IMG_TAG_COLOR_SPACE` tag and transmit current-working-space linear RGB while
preserving alpha/data channels and original source output.

Cross-config display requires defined interchange roles; missing roles produce
a diagnostic. Public references include
[Houdini's Color interface](https://www.sidefx.com/docs/houdini/hom/hou/Color.html)
and [the image-device tag vocabulary](https://www.sidefx.com/docs/hdk/_i_m_g___tags_8h_source.html).

The probe also records file-rule matches and rule indices. In this active
configuration, EXR selects Linear Rec.709 and PNG selects sRGB through specific
rules, while an unmatched HDR name reaches the default ACES2065-1 rule. Do not
assume that default-rule resolution should override the engine's file-format
heuristics. Houdini documents `HOUDINI_OCIO_FILENAME_COLORSPACE` modes 4 and 5
as suppressing a default-only result; mode 4 uses an optimized evaluator and
mode 5 the OCIO library. Verify the chosen native Auto precedence with real
header metadata and the configured mode. The
[environment-variable reference](https://www.sidefx.com/docs/houdini/ref/env.html)
supports this distinction. That additional policy was absent at the time of
this probe; the [native Auto route](notes/native-texture-auto.md) now implements and
tests all six modes against frozen definitions.
