# Blender 5.3 candidate: DLSS IPR

The isolated candidate retains its authored denoising defaults. Choose DLSS Ray Reconstruction under Interactive Sampling and Denoising to opt in. Final Render still offers Automatic, OIDN and OptiX; core validation rejects DLSS for final sessions.

The viewer resolution percentage and linked zoom define the output display dimensions. DLSS quality defines the tracing buffer relative to that target: Native 1, Quality 1.5, Balanced 1/0.58, Performance 2, Ultra Performance 3. The engine owns denoised versus noisy/data pass dimensions, jitter, temporal reconstruction and total sample scheduling. There is no additional sample cap. Internal reconstruction guides are engine auto passes and are not added to the user output pass catalogue.

RC Cycles uses one camera/object motion source for shutter-space user vectors and interactive history. With explicit Motion Vectors or shutter motion blur, the candidate preserves those authored semantics and uses the Automatic conventional denoiser. The viewer's effective backend and the structured `render.dlss_motion` warning make that substitution visible. Removing the conflicting setting restores DLSS. DLSS camera/object transforms retain previous-render history during continuous movement. Hard resource/optics/output changes publish one session history epoch at the serialized scene boundary. The render thread sends NGX Reset on the first successful frame of that epoch and on feature recreation; failed evaluations retry the reset. This preserves the existing NGX instance during scene edits. Continuous camera/object poses keep their valid reprojection history. Deformation uploads conservatively reset history until deformation reprojection is certified.

The Windows build enables DLSS and Image Iris by default. CMake uses the pinned NVIDIA headers in `third_party/dlss`. The build script accepts `-DlssSdkRoot` for an explicit compatible SDK. NGX initializes with `NVSDK_NGX_CUDA_Init_with_ProjectID` and creates Ray Reconstruction with `NVSDK_NGX_CUDA_CreateFeature`. Both calls use the Houdini integration’s project identity. The NVIDIA driver supplies the runtime. Device menus use capabilities reported by the render worker, so opening the menu incurs no NGX probe on Houdini’s UI thread. A saved selection remains editable while the capability check is pending or unavailable.

Local clapper and Render to Disk jobs hold nested IPR suspension leases. They pause running local sessions, retain their scene and image, and resume them after the last local final completes, fails or is cancelled. User-paused, stopped, failed, closed or replaced sessions are not restarted. The clapper keeps the final image in its viewer while retaining the previous IPR ownership; Play reconnects it. Closing the viewer does not abandon the background-job lease. Remote farm submissions do not acquire a local suspension lease.
