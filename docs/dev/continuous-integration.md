# Workstation CI

Provision the hash-locked pytest wheels with `./scripts/bootstrap-test-deps.ps1 -Download`. Install Ruff 0.14.3 and clang-format 18.1.8. Pass `-Wheelhouse`, `-Ruff` or `-ClangFormat` for custom paths. Run `./scripts/install-workstation-ci.ps1` once from PowerShell 7 in a trusted checkout. It installs a repository-local post-commit hook and a queue task under the current Windows user. The workstation must have that user logged in, a Houdini license, Blender, the locked SDK/toolchain, and the qualified local engine dependencies. An existing hook configuration is detected before installation. The post-commit hook exits successfully without enqueuing when the local runner setting is absent or empty.

The task invokes the copy of the runner installed in the CI state directory. After changing only the runner, use `./scripts/refresh-workstation-ci-runner.ps1` from PowerShell 7 in the owning production checkout. It atomically replaces and hash-checks that copy without changing either scheduled task, triggers, nightly state, configuration or queue. `-WhatIf` previews the target. A running drain keeps its loaded code; the next scheduled invocation uses the refreshed copy. Use the installer when changing installation settings. The hook queues the exact commit from any worktree. Every five minutes a single runner drains the queue into a private checkout and incremental build under `<project>/_work/ci` (until 22 November 2026 `%USERPROFILE%/.cycles-houdini/CI`; an existing installation keeps the place recorded in `.git/houdini-ci.json` until it is installed again). Its `checkout/third_party` is a directory junction to the project's `third_party`: never delete the CI state with a plain recursive delete (see [working folders](README.md#working-folders)). A green fast run also saves a recovery set; a new installation saves them in `<project>/_work/recovery` unless `-RecoveryDirectory` names a folder on another disk. The runner checks formatting, builds the exact commit, runs its tier, and audits the resulting manifest and evidence. The checkout reads the production dependency directory and verifies its revisions. Stage and test preferences belong to the run. The maintainer can select Nightly in the heavy renderer launcher or enqueue a revision explicitly with `python scripts/workstation-ci.py enqueue nightly <revision>`. CI setup disables the project's former daily trigger on upgrade. Use `-StateDirectory` to select a different location.

On Windows, runner children use `CREATE_NO_WINDOW` while retaining their log streams, exit codes and process-job containment. Tool and recovery subprocesses use `python.exe`, even when Task Scheduler starts the runner with `pythonw.exe`: Windows ignores that console flag for `pythonw.exe`, allowing its own console children to reopen a terminal. The console interpreter launched with the flag keeps the tool descendants windowless too. No build or test timeout changes are needed.

To exercise the runner immediately, run these commands from the production checkout.

```powershell
python scripts/workstation-ci.py enqueue fast HEAD
python scripts/workstation-ci.py drain
```

Each revision has a receipt, build manifest, log and tier evidence under the CI state's `results` directory. A failed build or test produces a failed receipt. For a deliberate retry, retain that evidence by moving the job's result directory aside and enqueue the revision again. To disable the local installation, disable both `CyclesHoudini-<repository ID>` tasks in Task Scheduler and unset this checkout's `core.hooksPath` if it still points to `.githooks`.
