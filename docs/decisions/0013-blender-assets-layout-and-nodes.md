# Blender assets: folder layout, Blender File node and Blender Hierarchy object

Accepted 2026-11-13. Imports from `.blend` files (asset browser and File > Import > Blender) wrote converted geometry, copied textures and several manifests into scattered folders (`geo/assets_blender`, per-material texture folders, hashed names), and an import could not be refreshed after the `.blend` changed. The artist asked for one predictable project layout, textures that stay in the library until he collects them, and a node per import that updates from Blender. [Implementation contract](../dev/blend-import.md)

Decision:

- **Textures stay in the library.** Imports read textures where the `.blend` points; only images packed in the `.blend` are extracted. **Cycles > Collect Textures** copies them into the project on request.
- **One folder per .blend.** `$HIP/assets_blender/<blend>/geo/<asset>/` holds converted geometry and `<blend>/tex/` extracted and collected textures; real names made safe for Windows, `_2` on a clash, no hashes. An unsaved scene writes the same layout under the user cache.
- **One JSON per blend folder.** `cycles_import.json` records the source, each asset's options, files and the scenes using it, and each image's origin. A re-import replaces only the files it lists, and asks before changing files another saved scene uses.
- **Collect, Relink, Move into Project** are menu actions on the host's **Cycles** menu: Collect copies textures into `<blend>/tex` (or `$HIP/tex/<material>`) and reports what is still not portable; Relink matches missing files by name under a chosen folder and never guesses; Move into Project moves cache imports into `$HIP/assets_blender` and is offered once after the first save.
- **Worlds.** Cycles has one world: a simple HDRI world becomes an Environment Light, any other a Cycles World Material. When the scene already has environment lighting the import asks **Replace** (the new one becomes active, the others are disabled) or **Keep existing** (imported disabled).
- **Every object/collection import lands on one of two nodes.** The **Cycles Blender File** SOP (`cycles::blender_file`) holds one asset in **Link** mode (the native reference inside) or **Converted** mode (a packed file or Stash in .hip), with Status, Update, Open in Blender, Load As and Part. The **Cycles Blender Hierarchy** object (`cycles::blender_hierarchy`) holds the importer's Hierarchy structure, editable inside, with the same Update. **Update All Blender Files** updates every node whose source changed. The native `cycles::blender_reference` stays installed but is hidden from the Tab menu.
- **Merged is replaced by Load As.** One converted file per asset, always packed; **Load As > Unpacked** with Iterations unpacks it on the node, so no second file is written.

Consequences: a project folder can be moved as a whole once its textures are collected and Link nodes are switched to Converted. Update never overwrites appended materials or nodes the artist added or moved. Imports made with earlier builds (plain File, Stash and Blender Reference nodes, the old folders and manifests) still load and render, but Update does not support them and nothing migrates them; importing again creates the new nodes. Stash in .hip makes the `.hip` larger with every saved version.
