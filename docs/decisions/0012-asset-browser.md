# Browse Blender asset libraries in an optional, worker-indexed panel

Accepted 2026-11-12. Artists keep reusable objects, collections and materials in Blender asset libraries. The existing bridge can render a named object or collection from a `.blend` file and translate materials, but finding an asset required knowing its file and exact name. Blender's own listing format (`_asset-library-meta.json`) is only present when someone generated it, and generating it writes into the library. [Implementation contract](../dev/asset-browser.md)

Add a dockable **Cycles Asset Browser** Python panel. By default it indexes libraries through the existing disposable Blender worker. The worker reads marked assets, catalogs and stored previews with `bpy.data.libraries.load(..., assets_only=True)`. Thumbnails and records go into a Houdini-side cache keyed by each file's signature. Library folders stay read-only. A per-library provider switch can instead read an existing Blender listing; generating one is a separate, confirmed action. Objects and collections import as `cycles::blender_reference` SOPs. Materials are rebuilt through the existing material translator, which translates completely or reports why it cannot.

Ship the browser as an optional Setup component, `blenderbridge\assetbrowser`, under the bridge. Its pane tab, shelf and help page live in `houdini/addons/asset_browser`, outside the always-loaded host folders. The install tool adds that folder to the package `hpath` only when the component is selected and writes `CYCLES_HOUDINI_ASSET_BROWSER=1|0`. Legacy receipts and first installs without an explicit choice default to off. Repair and registration refresh keep the stored choice. A disabled bridge disables the browser. An explicit request for the browser without the bridge is refused. Development packages include the add-on by default.

Consequences: an installation without the component has no browser UI, and its payload is unchanged because the add-on files ship in every immutable version. Indexing costs one Blender run per changed file batch. Cached results stay browsable without Blender. Append (copy) for objects and collections, non-mesh object types, and drag and drop remain future work; drag is an experimental, default-off setting.

Amended 2026-11-12, at the artist's request:

- **Materials import in Link or Append mode.** Link creates one shared node per library material. Its parameters are locked, and it can be reloaded from the library or made local. Append creates an editable copy.
- **The add-on adds menus.** Linked-material actions are in a node right-click submenu (`OPmenu.xml`) and in a **Cycles** menu of the network editor (`NetworkViewMenu.xml`), whose items work only in material networks. Houdini cannot hide a menu-bar entry per network type.
- **One Cycles shelf and a Cycles main menu (later the same day).** The optional add-on appends Asset Browser to Cycles Tools with a Houdini shelf edit. Disabled sessions load the base shelf. The host defines a **Cycles** main menu beside Labs with **Render View**. The add-on adds **Asset Browser** to it. The menu opens windows, and renderer actions stay on the shelf.
