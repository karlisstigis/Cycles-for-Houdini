# Documentation

| Folder or file | Who it is for |
| --- | --- |
| [user/](user/README.md) | Artists: installing, the render settings, materials, the asset browser, troubleshooting |
| [dev/](dev/README.md) | Developers: the developer guide (start here), architecture, building, tests, release |

| [dev/provenance/](dev/provenance/) | Behaviour descriptions and provenance of code that reproduces another program's behaviour |

| [history/](history/README.md) | Dated records of past measurements, reviews and changes that decisions cite |

The engine patch records stay at this level because every file in `patches/` names
`docs/renderer-patch-contracts.md` in its header, and the patch files are locked by their hashes in
`source.lock.json`:

- [renderer-patch-contracts.md](renderer-patch-contracts.md): what each patch must do and the tests related to it
  (generated by `scripts/patch-inventory.py`).
- [renderer-patch-coverage-audit.md](renderer-patch-coverage-audit.md) and
  [renderer-patch-test-recipes.md](renderer-patch-test-recipes.md): how far the patches are covered by tests,
  and how to run those tests.
- [patch-triage.md](patch-triage.md): which patches could go upstream and which stay in the fork (generated by
  `scripts/patch-triage.py` from `patches/triage.json`).
- [upstream-patches.md](upstream-patches.md): the record of the early patches and how they were verified.

`experiment-archive.json` lists files removed from the main line and kept in the private development archive; a test
reads it.
