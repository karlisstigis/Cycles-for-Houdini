# Optional image iris

Image iris is a separately compiled native camera feature, included by default in this project's builds (`CH_IMAGE_IRIS=ON`). The build script enables it without an extra flag. Disable it only when explicitly requested, using `-ImageIris:$false` or `-DCH_IMAGE_IRIS=OFF`. The default analytic circular or blade aperture remains available. A build without the feature rejects an explicitly requested image aperture rather than silently replacing it.

Depth of Field and its nested Image Iris panel each have an enable checkbox in the panel header. Image Iris owns Image, Use Color and Sampling Method. Blades is disabled and ignored when Image Iris is enabled; Rotation and Ratio continue to shape the image aperture. Ratio follows Blender's slider range of 0.01 to 2, with larger values accepted by typing.

The camera's image-iris sampling menu offers **CDF** (the default) and **Hierarchical**. Both sample the same nonnegative bilinear image density. They change the mapping from Cycles' existing lens random dimensions to aperture positions; they do not change the intended bokeh or exposure. At finite sample counts, their noise and structured sample patterns can differ. Neither method is guaranteed faster or cleaner for every mask.

By default the image supplies scalar intensity: RGB images use linear luminance, grayscale images use their scalar value, and alpha masks the transmission. It is normalized to unit integral, so multiplying every pixel by a positive constant does not darken the render. Black images, damaged files and invalid values are rejected before replacing an accepted scene. Fixing the file at the same path is detected during IPR.

**Use Color** is an optional camera toggle, off by default. It treats RGB pixels as linear color transmission and produces colored bokeh. Grayscale images and neutral RGB images remain neutral. Image data is read as raw linear values in the renderer's working RGB basis, without an implicit display transform: prepare the image in that basis rather than assuming an encoded display image will be linearized. Alpha masks RGB transmission once. The color toggle does not alter geometric coverage alpha.

Cycles retains a scalar alpha channel rather than a spectral transparency description. Geometric coverage, full holdouts and achromatic material transparency remain independent of the iris tint; opaque-surface Cryptomatte coverage and Mist weights also retain their geometric meaning. Colored material transparency can change the scalar alpha because the camera filter changes the channel contributions: the transparent contribution is `average(C * M) / average(C)`, where `C` is the initial RGB camera weight and `M` is the path's material transmission. This preserves neutral transparency without discarding the interaction between a colored filter and a colored transparent surface. A scalar alpha cannot represent every possible spectral compositing result.

The sampling density is proportional to `A = 0.2126 R + 0.7152 G + 0.0722 B`, including the alpha mask. The camera ray receives the RGB weight `T / A`, where `T` is the bilinearly evaluated RGB transmission at the sampled aperture position. This gives the same scalar aperture normalization in both modes and retains the filter's average tint. For a constant transmission color, the rendered color multiplier is `T / luminance(T)`. There is no per-channel white balancing. Multiplying the entire mask by a positive scalar leaves exposure unchanged; multiplying only one channel changes tint. This is exposure-compensated RGB transmission, not an absolute light-loss/T-stop or spectral simulation. It also does not simulate diffraction, lens aberrations, sensor spectral response or lens housing occlusion.

Color-coded physical apertures do produce channel-dependent defocus. [Bando, Chen and Nishita (2008)](https://web.media.mit.edu/~bandy/rgb/) demonstrate a real RGB-filtered lens aperture whose defocused channel images shift according to the filter positions; the shifts reverse across the focus plane and converge at focus. Unequal filter transmission can also tint the overall image. [Chakrabarti and Zickler (2012)](https://vision.seas.harvard.edu/ccap/) use a spectrally varying aperture to give channels different depths of field. This feature models that geometric RGB-filter behavior; arbitrary RGB image values are an approximation to a physical filter's wavelength-dependent transmission.

Those color-coded aperture papers use the optical behavior for depth reconstruction; this renderer feature uses their measurements to validate the filter behavior, and performs no depth reconstruction. A realistic multielement lens model is a different feature. [Hanika and Dachsbacher (2014)](https://cg.ivd.kit.edu/publications/pubhanika/2014_lenssim.pdf) model real lens systems through wavelength-dependent polynomial ray mappings, including optical aberrations. The current image iris does not implement that lens simulation or generate chromatic aberration automatically from an uncolored aperture.

Image distributions are immutable and reused when only color transmission, sampling method, focus, aperture size, rotation or ratio changes. Changing the image contents rebuilds the distribution in the renderer worker, away from Houdini's main thread. Both CDF and hierarchy tables and RGB transmission data are prepared together so those camera toggles do not decode the image again.

## Comparison and validation

`tests/core_image_iris_smoke.py` invokes `ch_harness --image-iris-render` on each requested device. Its output directory includes:

- `bokeh-cdf.exr` and `bokeh-hierarchical.exr`, rendered with the same scene, seed and 2048-sample budget.
- `bokeh-rotated.exr`, a 90-degree aperture rotation.
- `bokeh-comparison.png`, left to right: CDF, hierarchy, rotated hierarchy. The panels share exposure and a display gamma of 2.2; use EXRs for numeric evaluation.
- `comparison.json`, containing energy, centroid, covariance, observed render wall times and image differences. These tiny renders verify behavior, and do not predict production-scene performance.

The native test also checks constant-world radiance against an analytic expectation, changes mask intensity by tenfold, switches sampling methods, changes focus and ratio, and damages/removes/repairs the mask while a persistent IPR generation is tracing. A disabled build checks the analytic path and explicit rejection of the unavailable feature.

`tests/core_image_iris_color_smoke.py` invokes `ch_harness --image-iris-color-render` for optional color transmission. It checks analytic uniform-field tint with perspective, orthographic and panorama cameras; grayscale, neutral RGB and alpha-masked images; color-off neutrality, coverage-alpha preservation, full holdouts, neutral transparency and analytically normalized colored material transparency; independently integrated channel bokeh centroids and energy ratios with both samplers; focus convergence and foreground reversal; live image edits and rejected-image repairs; resource reuse and shutdown. Its artifacts include `colored-bokeh-cdf.exr`, `colored-bokeh-hierarchical.exr`, `colored-bokeh-foreground.exr`, a shared-exposure `colored-bokeh-comparison.png`, and numeric `comparison.json`.

Mitsuba documents both [hierarchical and marginal distributions](https://mitsuba.readthedocs.io/en/v3.6.3/src/api_reference.html). The original [hierarchical sample-warping paper](https://cs.dartmouth.edu/~wjarosz/publications/clarberg05wavelet.html) illustrates the distribution mapping. Those illustrations are not a side-by-side image-iris CDF versus hierarchy bokeh comparison; the artifacts above provide that comparison for this integration.

For an interactive visual comparison of marginal/conditional and hierarchical warping (using environment maps rather than aperture masks), see [Matt Pharr's original comparison](https://pharr.org/matt/blog/2019/06/05/visualizing-env-light-warpings).
